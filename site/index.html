Cloud and AI infrastructure, designed to be run.

CloudLab Works is a working lab and a place to collaborate live on projects: hybrid multicloud, AI infrastructure from the rack to the region, agentic systems that run real infrastructure, and technical writing that shows the work. Current interests: osmotic communication between agents, multi-agent swarms, advanced harnesses, next-generation routing (graph-based), and self-learning systems.

Written for the engineer who has to build it, not the slide that has to sell it. Whole system first, then the parts; every design grounded in what it costs to operate.

Public Projects

The lab's project board, the parts that can be shown. Status is the board's word for it; the full plans, diagrams and decision trail sit in the private back office, and the decisions themselves are public in the Architecture Decision Record. Identifiers are masked the same way: no hostnames, addresses or figures.

  • Infrastructure as Music activeSound generated from lab state, never a playlist: Sonic Pi phrases, a state-driven drone, a recorder and a nightly episode builder, played by agents and automations. Live on Code as Music; code at issaquahd/infrastructure-as-music.
  • cloudlabworks.dev activeThis site: one Cloudflare Worker, static build, self-hosted scripts, no third-party trackers; the blog, the art, the music and the decision record all ship from one repo. issaquahd/cloudlabworks-site.
  • Duvall lab, the rebuild reviewedThe plan behind everything else here: a 6U rack, UniFi routing with five VLANs and 10G to the workstation, a Turing Pi 2 cluster in a Jonsbo N4 with a mirrored storage pair, a Proxmox sandbox tier, and a Mac as the only inference host. Reviewed in the open with a peer agent, three correction passes.
  • Turing Pi 2 in a Jonsbo N4: storage and layout reviewedSlot-by-slot layout for four ARM compute modules, an NVMe tier and a mirrored spinning pair; ARM-only images, so multi-arch is a build rule, not an assumption. Buy list sized against the case, not the wish.
  • WAN failover for live demos decidedA 5G backup on the gateway's second WAN so a demo survives the fiber. Cheaper routes (phone hotspot, travel router) reviewed and rejected on cutover time.
  • Home to lab observability, one dashboard proposedHouse sensors and lab health on one board, so a power blip and a failed deploy are read in the same place. First cut of the plan; the watchdog it needs is on the test list.
  • Closing the per-trajectory gap activeAgents claim work is done; this makes them prove it: a per-task ledger where every "done" carries a receipt the verifier checks against the system, never against the transcript. In use for every multi-step task in this lab.
  • Replay worlds for our own loops proposedRerun an agent's past trajectory against a recorded world before letting a change loose on the live one. What transfers from the research is the mechanism, not the benchmark.
  • AHV dev sandbox proposedA browser terminal into a per-user agent VM: untrusted skills and pipelines get a place to run that is not production. Design sketch, untested.
  • Draftpad sketch to infrastructure intent proposedA gridded desk mat, a phone photo, and a diagram-to-code step: draw the topology by hand, get the intent file back. Filed after a peer-agent answer on how far the recognition can be trusted.
  • Open WebUI as the lab's front door builtLocal models on the box behind a single sign-in, with the lab's own tools attached. The private half of the estate, described here, not shown.
  • Three sites, one estate draftPublic site, private back office, and the household frame: what each audience sees, and the one identity layer in front of the private half.
  • Peer-agent thinking pass builtA skill that runs a divergent-then-convergent pass over a shared thread and reports privately to one person. Briefed to a second agent for consensus before the twenty-minute build.
  • Mac Studio test and staging plan proposedHow the next inference host gets tested before it takes over: model lanes, local-only jobs, and what stays on the current machine.
  • Workflow engine fit: n8n, Open WebUI, Cloudflare draftWhether a visual workflow engine beats the scheduler already running the lab. Answer so far: for the human-in-the-loop parts, maybe; for the nightly jobs, no.
  • Light show for Infrastructure as Music parkedAn LED sphere driven by the same lab state as the music. Parked on purpose: the stock firmware's sync-to-music mode already does the job.
  • Earlier, on GitHubNC2 field tooling and study guides from the Nutanix years: nc2costexplorer, nc2azureazurevm, Terraform_ERA (DBaaS as code), CloudClusters, NCP-MCI, home_automation_duvall. Everything under @issaquahd.

Services

  • Cloud & AI triageFor small cloud-native shops with something already running that no longer behaves: an agent stack with runaway tool calls or a memory that forgets, a cluster nobody wants to touch, a pipeline that fails on Fridays, a bill that doubled. Containers, Kubernetes, Workers, OpenTofu and Ansible on AWS, Azure, Google Cloud and Cloudflare. Read the current state, find the fault, fix the smallest thing, leave a runbook the team can follow next time.
  • Early-stage startup advisorPre-seed to seed, infrastructure and cost. What to build on, what to rent, what it will cost to run at ten customers and at a thousand, and which vendor terms bite once dependency sets in. A standing hour, a read of the plan before the raise, or a seat at the table when the architecture gets decided.
  • Agentic artOriginal pieces from the lab's own pipeline: Coast Salish-vocabulary formline drawn in code, nightly pieces cut from the lab's music, badges and marks for a site or a product. See Code as Art. Commissions welcome; the code ships with the piece.
  • Board positionsAdvisory and non-profit boards where twenty years across cloud, data center, finance operations and sales engineering are useful: technology direction, vendor selection, FinOps discipline, and the questions to ask before the money moves.
  • Community give-backsTalks, workshops and mentoring for user groups, schools and students, at no charge: cloud fundamentals, agentic systems for people who run infrastructure, how to read a cloud bill. See Mentoring and Volunteering.

Alex's story

Alex Alvord grew up in the Pacific Northwest, navigating it with his hands and feet. With a long career in cloud and IT behind him, he dives head first into the magic AI can provide with the right harness and tooling: osmotic communication, multi-agent swarms, advanced harnesses, next-gen routing built on graphs, and systems that learn from their own runs.

His background runs through Raku-fired ceramics, glass art, pottery, and painting; he mixes mediums with the Pacific Northwest's great driftwood coast. The work, and what feeds it, is on the Art as Code as Art page.

By trade: an Advisory Solutions Architect, Hybrid Multicloud, whose career has run through cloud, data center, and infrastructure software. Certifications include AWS Solutions Architect – Professional, Microsoft Azure Solutions Architect Expert, Google Professional Cloud Architect, and Nutanix NCP-CI for AWS and for Azure (Cloud Integration), the NC2 exams he helped write before sitting them himself. He founded the Seattle Nutanix User Group and works from a home lab in Duvall that doubles as the test bench for everything published here. Projects, career, recognition, and code →
