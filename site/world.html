Code as World

A world represented as code, not just pixels: its composition, its dynamics and its appearance live in one small Python module, and the lab's own coding agent writes, steps and renders it locally. This is the first run, v0.1: one world, one seed, three frames. The dynamics are a script, not a solver. Every rule is a line you can read. A physical-simulation backend (MuJoCo) stays in reserve for the one scene that actually needs a solver instead of a script; this one does not.

Source: media/src/world/world.py (composition, step, render) and gen.py (seed it, run it, write the frames). Stdlib only, no model in the loop at render time. Same seed, same world, same frames.

The world, as code

Three parts, named the way the Code-as-World paper names them. The composition is a list of entities: a sun, the water with its tide and current, a headland and an island, a canoe (mass, floats, the one loud colour), an orca (mass, neutrally buoyant, a swim speed and a dive cycle), a heron, three clouds. The dynamics are the step function below: a sinusoidal tide on the water level, a sun arc, a current that follows the tide and drifts the canoe, an orca that swims and rides a dive cycle, a heron that stays put. The appearance is render: the state as flat shapes, 1200 by 900, earth tones first and one loud colour against them.

The second world: Kyoto

A temple-garden pond scene: a torii gate on the far bank, a stone lantern and a cherry tree on the near one, a koi swimming its lane, twelve petals falling and drifting on their own fixed cycles, one afternoon into dusk. Same three-part split, same discipline. Source: media/src/world-kyoto/kyoto.py and gen.py.

Where it came from

How it started: a stake sign on the Work page while the idea was scoped. Two papers set the shape. Code-as-World (MirroS Lab, "Agentic Discovery of Executable World Representations for Physical Reasoning") gave the three-part split, composition, dynamic evolution and visual appearance as executable code, and the loop of propose, execute, render, verify, refine that produced this run. Code World Model (Westlake AGI Lab / NTU, "Coding Agent as World Brain") gave the framing that the coding agent itself keeps the persistent world state and re-renders it, which is why state.json is on this page and not only the pictures. Reviewed with Pickles before ground was broken.

Next: a second world, and the first scene that needs something to fall, bounce or stack, which is the one MuJoCo is reserved for.
