## Article

**Title:** NC2 on Google Cloud: a plan — Pulumi, and the v4 API only

**Cover image:** gcp-plan-01-map.png

Nutanix Cloud Clusters doesn't list Google Cloud as a supported platform. Only AWS and Azure, today, in the public deployment guides — the same guides the last two posts in this series walked exactly as written. So this one is a different kind of post: not a report on a shipping feature, a plan for the closest honest equivalent on GCP, with two constraints handed to the lab on purpose — Pulumi as the IaC tool instead of Bicep or OpenTofu, and once Prism Central exists, only the v4 API touches it, because there's no NC2 v2 API on GCP to reach for. Full detail and every code block: https://cloudlabworks.dev/nutanix/nc2-gcp-plan-pulumi-v4-api-only

**The honest map**

[image: gcp-plan-01-map.png]

The gap between what NC2 does for you on AWS/Azure and what this plan does by hand is the whole first half of this post. Networking is ordinary GCP practice. Foundation is the part every NC2-on-AWS/Azure reader never sees, because the console did it there — here it's driven by hand, unmodified from how it's always worked on-prem.

**Step 1: the substrate — Sole-Tenant Nodes, not general-purpose VMs**

[image: gcp-plan-02-substrate.png]

AHV needs nested virtualization: real hardware-assisted virtualization exposed to the guest. GCP's answer is Sole-Tenant Nodes, the feature built for exactly this class of problem. UNKNOWN and stated plainly: whether Nutanix's own licensing and hardware-compatibility list treats this shape as a supported AHV target at all — an architecture question answered here, a licensing conversation that isn't.

**Step 2: the landing zone, in Pulumi**

[image: gcp-plan-03-landingzone.png]

Same shape as the Bicep landing zone in the Azure post, written as a Pulumi program because that was the ask: a VPC per NC2 concern, Cloud NAT for egress, a Sole-Tenant Node group standing in for the bare-metal capacity NC2 racks for you elsewhere.

**Step 3: Foundation — the part NC2 usually hides**

[image: gcp-plan-04-foundation.png]

The single largest open question in the whole plan, and it's flagged as one instead of glossed over: Foundation's usual imaging path assumes IPMI-like out-of-band access a Sole-Tenant Node instance doesn't provide the way a physical rack does. A custom GCE image booted directly is the likely shape; it is not verified here.

**Step 4 and 5: Prism Central, then the v4-API-only line**

[image: gcp-plan-05-apiline.png]

Once Prism Central answers on 9440, this plan converges onto exactly what the AWS and Azure posts already practice: every VPC, subnet, image and VM is a v4 resource, managed through Pulumi bridged from the official Nutanix Terraform provider (`pulumi package add terraform-provider nutanix/nutanix`) instead of OpenTofu. Same v4 surface, same ETag-based safety against a colleague's console click, different IaC tool.

**What this plan gets right and where it's honest about not knowing**

- Right, and reusable today: the v4-API-only discipline itself, and Sole-Tenant Nodes as the nested-virtualization substrate — that part isn't a guess, it's documented GCP practice.
- UNKNOWN, stated plainly: Nutanix licensing/HCL support for this hardware shape, the Foundation-without-IPMI imaging path, and whether any of this maps to an actual Nutanix roadmap item. None of the three are answered by a diagram, and this post doesn't pretend they are.

Full plan, every code block, every UNKNOWN: https://cloudlabworks.dev/nutanix/nc2-gcp-plan-pulumi-v4-api-only
